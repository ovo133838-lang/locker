# 计费规则与算例

> 规则来自需求说明书 3.2 / 3.3 与附录 A；日单价来自原型（需求书表 3-2 未列，列为待确认 Q8）。金额全部以分计算，本文件的「元」仅为阅读方便。

## 1 价格表（默认）

| 柜型 | 免费时长 | 计时单价 | 24h 封顶 | 日单价 | 押金 |
| --- | --- | --- | --- | --- | --- |
| S 小柜 | 10 分钟 | 500 分/时（5 元） | 5000 分（50 元） | 1500 分（15 元） | 1000 分（10 元） |
| M 中柜 | 10 分钟 | 700 分/时（7 元） | 7000 分（70 元） | 2500 分（25 元） | 2000 分（20 元） |
| L 大柜 | 10 分钟 | 1000 分/时（10 元） | 10000 分（100 元） | 3000 分（30 元） | 3000 分（30 元） |

## 2 计时模式

1. 实际分钟数 `m`，若 `m <= free_minutes`（10）→ 费用 0，已付全额退回。
2. 超出免费时长后按**实际总时长**计费，免费时段不抵扣。
3. 计费单位 0.1 小时：`units = ceil(m / 6)`（每 6 分钟一个单位，不足 6 分钟按 6 分钟计）。
4. 每 1440 分钟为一个收费区间，跨区间逐段累加；每段金额 = `min(段内 units × price_amount / 10, cap_amount)`，四舍五入到分。
5. 不允许把 3 小时按 4 小时收（不进位到整小时），也不允许总时长直接套一次封顶。

## 3 按日模式

`days = ceil(m / 1440)`，费用 = `days × daily_amount`，同样受日封顶约束（`daily_amount <= cap_amount` 由保存规则时校验）。

## 4 结算

```
actual_fee = CalcFee(rule_snapshot, size, actual_minutes)
refund     = paid_total - actual_fee        // 可为负
```
- `refund > 0`：原路退回，订单 `closed`。
- `refund = 0`：直接 `closed`。
- `refund < 0`：订单 `overdue`，`extra_amount = -refund`，必须先补交才能开门与关单。
- 退款失败不回滚关单，写异常转人工；已补交金额不因开门失败而回退。
- 免费时长内结束：`actual_fee = 0`，已付全额退回（含押金）。

## 6 函数契约

```go
type RuleSnapshot struct {
    Mode        string // hour | day
    FreeMinutes int
    Sizes       map[string]SizeRule // S/M/L
}
type SizeRule struct {
    PriceAmount   int // 分/小时
    CapAmount     int // 分/24h
    DailyAmount   int // 分/天
    DepositAmount int
}
type FeeDetail struct {
    Units       int   // 计费单位或天数
    Segments    []Segment
    CapHit      bool
    BaseAmount  int
    FreeMinutes int
}
func CalcFee(rule RuleSnapshot, sizeCode string, minutes int) (FeeDetail, error)
```

要求：纯函数、无 IO、可用表驱动测试；下单预估、结束结算、后台复算、小程序展示全部调用同一实现。

## 7 常见错误

| 现象 | 根因 | 正确做法 |
| --- | --- | --- |
| 0.30000000000000004 | float | 全用分 |
| 3 小时收 4 小时钱 | 进位到整小时 | 0.1 小时精度 |
| 26.5 小时超封顶 | 封顶按总时长套 | 每 24h 区间单独取 min |
| 退款等于押金 | 押金直接退 | 退 paid_total - actual_fee |
| 预估与结算不一致 | 前端另算一套 | 统一调用后端 CalcFee |
| 改价影响进行中订单 | 读最新规则 | 读 rule_snapshot |
